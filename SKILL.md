# Спросить Gemini (через десктопное приложение)

Отправить вопрос в приложение Google Gemini (`%LOCALAPPDATA%\Google\Gemini\Gemini.exe`, тот же аккаунт и подписка) с помощью Windows UI Automation и вернуть текст ответа в ZCode.

Веб-версию через browser-use НЕ использовать — пользователь явно просит работать через приложение. Само приложение блокирует `--remote-debugging-port`, поэтому CDP недоступен, а UIA работает.

## Команда

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME/.agents/skills/ask-gemini/scripts/gemini_ask.ps1" -Question "ТЕКСТ ВОПРОСА"
```

Передать весь вопрос одним аргументом `-Question` (кавычки!). Таймаут Bash-вызова ставить не менее `MaxWaitSec + 120` секунд (по умолчанию ожидание ответа до 240 с). Можно передать `-MaxWaitSec N`.

Если ожидается генерация изображения (запрос «создай изображение…»), дополнительно передать `-ImageOut "C:\...\полный_путь.png"` — путь в рабочей папке проекта, куда сохранить картинку.

Если пользователь просит передать файл (просьба «передай файл», «отправь этот файл Gemini» и т.п.), передать `-FilePath "C:\...\полный_путь"` — файл кладётся в буфер обмена как файл (CF_HDROP, `Set-Clipboard -Path`) и вставляется в поле ввода через Ctrl+V, после чего приложение само прикрепляет его (печатать содержимое файла текстом в поле ввода НЕЛЬЗЯ — приложение может выдать отказ). Успешное прикрепление подтверждается строкой `ATTACHED <путь>`; коды выхода: 8 — файл не найден, 9 — файл не принят (чип с именем файла не появился).

Если ответ — большой блок кода (например, весь HTML), НЕ восстанавливать его из извлечённого UIA-текста (токены подсветки перемешивают строки): нажать кнопку `Copy code` у блока кода через InvokePattern и забрать чистый код из буфера обмена (`[Windows.Forms.Clipboard]::GetText`, сборка System.Windows.Forms; читать буфер в отдельном вызове PowerShell).

Формат вывода при успехе:

```text
ANSWER_START
<полный текст ответа Gemini>
ANSWER_END
```

Если Gemini вернул изображение (полноценный ответ-картинка или вместе с текстом), появляется строка:

```text
IMAGE_SAVED <путь к PNG>
```

Это screen-capture области `Image`-элемента (кнопка «Download full size image» в приложении НЕ скачивает файл надёжно — не полагаться на неё).

## Показ изображения пользователю (обязательно)

После каждой `IMAGE_SAVED` пользователь ДОЛЖЕН увидеть картинку прямо в ленте чата ZCode — путь к файлу вместо картинки не считается. Порядок (сам, без вопросов пользователю):

1. Прочитай PNG через Read — проверить содержимое (совпадает с запрошенным).
2. В финальном ответе выведи картинку ОДНИМ markdown-изображением с относительным от рабочей папки путём: `![описание](имя-файла.png)`. Ровно один вывод на картинку — не дублировать вторым способом и не выводить тот же файл с абсолютным file:// путём (пользователь увидит дубль).
3. Если markdown-картинка у пользователя не отобразилась — запасной способ: обернуть PNG в PDF через Pillow (`Image.open(png).convert('RGB').save(pdf, 'PDF', resolution=150)`) и открыть `mcp__plugin_pdf_pdf__open_document`.

Коды выхода и ошибки:

- `0` — успех, ответ между маркерами.
- `ERROR_NO_WINDOW` (2) — приложение не запустилось за 45 с: попроси пользователя открыть Gemini и проверить, что он залогинен, затем повтори вызов (скрипт сам запускает exe, если приложение закрыто).
- `ERROR_NO_EDITOR` (3) / `ERROR_NO_SEND_BUTTON` (4) — интерфейс приложения изменился (обновление версии): см. диагностику ниже.
- `ERROR_NO_ANSWER` / `TIMEOUT_NO_ANSWER` (5) или строка `TIMEOUT_PARTIAL` перед ответом — Gemini не завершил генерацию за `MaxWaitSec`: сообщите пользователю, можно повторить с бо́льшим `MaxWaitSec`.
- `IMAGE_CAPTURE_FAILED` — картинка сгенерирована, но снять область экрана не удалось (окно перекрыто/свёрнуто): попроси пользователя не трогать окно Gemini и повтори.

## Дальнейшая работа

После получения ответа: верни его пользователю (при необходимости переоформив markdown) и продолжай исходную задачу ZCode, учитывая ответ Gemini. Если пользователь просил именно "спросить", а не "продолжить", ограничься передачей ответа.

## Диагностика сбоев

Если скрипт возвращает 3/4 — элементы UIA переименованы обновлением приложения. Разведка: найди окно с именем `Gemini` через `System.Windows.Automation`, поле ввода — `Edit` с именем, содержащим `prompt` (у него должен работать `ValuePattern`), кнопка отправки — `Button` с именем `Send message`. Обнови регулярки в `scripts/gemini_ask.ps1` (`Find-Editor`, `'^Send message$'`, `'Stop'`, маркеры конца в `Extract-Answer`) и перепроверь на коротком вопросе.

## Особенности, которые нельзя сломать

- Перед вводом скрипт включает флаг screen reader (`SPI_SETSCREENREADER`), иначе Chromium в Electron не строит дерево доступности и `Edit`/`ValuePattern` недоступны; в конце скрипт возвращает флаг в исходное состояние.
- `ValuePattern.SetValue` — единственный надёжный способ ввести текст (SendKeys/Ctrl+V и клики по координатам в Chromium не срабатывают).
- Каждый запуск открывает новый чат (кнопка `New chat`), иначе границы ответа между вопросами в одном чате не отделить.
- Ожидание ответа = нет кнопки `Stop` + текст всех `Text`-узлов стабилен 3 подряд проверки по 2 с. Не сокращай стабилизацию до 1–2 проверок: между частями генерации бывают паузы > 2 с.
- Ответ-картинка не содержит текста после «Gemini said», поэтому завершение засчитывается и по новому `Image`-элементу с именем, содержащим `AI generated` (ширина > 100 px), появившемуся после отправки (их число сравнивается с baseline до генерации — старые картинки из чата не считаются). Захват — `Graphics.CopyFromScreen` по `BoundingRectangle` при активном окне; для захвата окно поднимается на передний план.
