# Спросить Gemini (через десктопное приложение)

Отправить вопрос в приложение Google Gemini (`%LOCALAPPDATA%\Google\Gemini\Gemini.exe`, тот же аккаунт и подписка) с помощью Windows UI Automation и вернуть текст ответа в ZCode.

Веб-версию через browser-use НЕ использовать — пользователь явно просит работать через приложение. Само приложение блокирует `--remote-debugging-port`, поэтому CDP недоступен, а UIA работает.

## Команда

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME/.agents/skills/ask-gemini/scripts/gemini_ask.ps1" -Question "ТЕКСТ ВОПРОСА"
```

Передать весь вопрос одним аргументом `-Question` (кавычки!). Таймаут Bash-вызова ставить не менее `MaxWaitSec + 120` секунд (по умолчанию ожидание ответа до 240 с), а **при генерации изображения или видео — не менее `MaxWaitSec + 420`** (после нажатия Download приложение докачивает blob и только потом открывает диалог сохранения: для картинок ~2–3 минуты; скрипт ждёт диалог до 300 с). Можно передать `-MaxWaitSec N`. Для долгого прогона удобнее запускать Bash-команду в фоне.

Если ожидается генерация изображения (запрос «создай изображение…»), дополнительно передать `-ImageOut "C:\...\полный_путь.png"` — путь в рабочей папке проекта, куда сохранить картинку.

Если ожидается генерация видео (запрос «сгенерируй видео…», «сделай видеоролик…»), передать `-VideoOut "C:\...\полный_путь.mp4"` и `-MaxWaitSec 420` (генерация Veo занимает ~4–7 минут; на выходе всегда ~10 с 1280×720 h264+aac независимо от запрошенной длительности). Ответ при этом текстовый («Ваше видео готово!»), картинка не создаётся.

Если пользователь просит передать файл (просьба «передай файл», «отправь этот файл Gemini» и т.п.), передать `-FilePath "C:\...\полный_путь"` — файл кладётся в буфер обмена как файл (CF_HDROP, `Set-Clipboard -Path`) и вставляется в поле ввода через Ctrl+V, после чего приложение само прикрепляет его (печатать содержимое файла текстом в поле ввода НЕЛЬЗЯ — приложение может выдать отказ). Успешное прикрепление подтверждается строкой `ATTACHED <путь>`; коды выхода: 8 — файл не найден, 9 — файл не принят (чип с именем файла не появился).

Если ответ — большой блок кода (например, весь HTML), НЕ восстанавливать его из извлечённого UIA-текста (токены подсветки перемешивают строки): нажать кнопку `Copy code` у блока кода через InvokePattern и забрать чистый код из буфера обмена (`[Windows.Forms.Clipboard]::GetText`, сборка System.Windows.Forms; читать буфер в отдельном вызове PowerShell).

Формат вывода при успехе:

```text
ANSWER_START
<полный текст ответа Gemini>
ANSWER_END
```

Если Gemini вернул изображение (полноценный ответ-картинка или вместе с текстом), появляются строки:

```text
IMAGE_SOURCE download | screen-capture
IMAGE_SIZE <W>x<H>          (только при IMAGE_SOURCE download)
IMAGE_SAVED <путь к PNG>
```

Основной путь — `download` (проверено 2026-11-13, E2E): скрипт нажимает кнопку `Download full size image` (правая из трёх кнопок в правом верхнем углу карточки картинки, `InvokePattern`). После этого приложение ~2–3 минуты докачивает blob и ОТКРЫВАЕТ НАТИВНЫЙ ДИАЛОГ «Сохранить как» (класс `#32770`, заголовок `blob:null/<guid>`, имя файла по умолчанию `Gemini_Generated_Image_xxx.jpg`), который остаётся висеть открытым, пока не нажмёшь «Сохранить»/«Отмена» — бросать его нельзя. Скрипт сам: находит диалог через raw `EnumWindows` (в дереве UIA от корня рабочего стола он НЕ виден), вводит полный путь в поле имени (control id 1001, `WM_SETTEXT`) — так файл сохраняется прямо в проект, — нажимает «Сохранить» (`GetDlgItem(dlg,1)` + `BM_CLICK`) и ждёт появления файла со стабильным размером. Затем перекодирует JPEG в PNG по `-ImageOut` и удаляет скачанный файл. Разрешение = оригинал (пример: 2752×1536). Если за 300 с диалог не появился, но в Downloads создался стабильный новый файл — берётся он (тот же `IMAGE_SOURCE download`).

`IMAGE_SOURCE screen-capture` — fallback (кнопка не найдена/не сработала или скачанный файл не декодировался): снимок экрана области `Image`-элемента, разрешение = размер картинки в окне.

Если Gemini вернул видео, появляются строки:

```text
VIDEO_SOURCE download
VIDEO_SIZE <байт>
VIDEO_SAVED <путь к MP4>
```

Механизм видео (проверено 2026-11-13, E2E): видео-карточка НЕ содержит элементов `ControlType.Video` и `Image` с именем `AI generated` — она распознается только по кнопкам с точными англоязычными именами `Download video`, `Share video`, `Mute video`, `Play video` (совпадение имени строго точное: в списке чатов слева есть кнопки `More options for …`, в заголовке которых может быть слово «видео»). Скрипт сравнивает число кнопок `Download video` с baseline до отправки (старые видео из чата не считаются), ждёт до 30 с после стабилизации текста (гонка, как с картинками), жмёт последнюю (`InvokePattern`; неактивна — повтор до 60 с), затем тот же диалог «Сохранить как» (`#32770`, `blob:`) с полным путём проекта в поле имени. Для видео диалог открывается быстро (единицы секунд — ~2 мин), но ждём те же 300 с. Скачанный MP4 перемещается ровно на путь `-VideoOut`, конвертации нет. `VIDEO_DOWNLOAD_FAILED` — видео есть, но сохранить не удалось (проверь висящий `blob:`-диалог и повтори заход через кнопку вручную нельзя — лучше повторно запустить скрипт с бо́льшим `-MaxWaitSec`).

## Показ изображения пользователю (обязательно)

После каждой `IMAGE_SAVED` пользователь ДОЛЖЕН увидеть картинку — путь к файлу вместо картинки не считается. Проверено на практике: markdown-изображение в ленте чата ZCode надёжно НЕ рендерится, поэтому НЕ начинать с него — сразу, не дожидаясь жалоб пользователя, показывать картинку в PDF-панели. Порядок (сам, без вопросов пользователю):

1. Прочитай PNG через Read — проверить содержимое (совпадает с запрошенным).
2. Заверни PNG в PDF рядом с ним через Pillow: `Image.open(png).convert('RGB').save(pdf, 'PDF', resolution=150)` (любой python с Pillow, в т.ч. встроенный `python\python.exe` проекта).
3. Открой `mcp__plugin_pdf_pdf__open_document` АБСОЛЮТНЫМ путём к PDF — рабочая папка плагина может не совпадать с текущей директорией сессии, относительный путь даёт `[not_found]`.
4. В тексте ответа ограничься обычной ссылкой на PNG-файл; не выводи ту же картинку вторым способом (markdown-картинкой или file://) — пользователь увидит дубль.

При `IMAGE_SOURCE download` разрешение = оригинал Gemini, разворачивать окно не нужно. Только при fallback `screen-capture` разрешение = размер `Image`-элемента в окне: если нужно выше, попроси пользователя развернуть окно Gemini на весь экран и повтори генерацию.

## Показ видео пользователю

PDF-панель MP4 не рендерит. После каждой `VIDEO_SAVED` (шаги те же, что и для картинок — без вопросов пользователю):

1. Извлеки превью-кадр: `ffmpeg -y -v error -ss 2 -in "<mp4>" -frames:v 1 "<video>-frame.png"` (ffmpeg/ffprobe в PATH, `C:\ffmpeg`). Кадром проверь, что видео совпадает с запрошенным.
2. Заверни кадр в PDF (Pillow) и открой в PDF-панели абсолютным путём — как шаги 2–3 для изображений.
3. В тексте ответа дай ссылку на MP4-файл и параметры из `ffprobe` (длительность, разрешение) — сам видеофайл в панель не класть.

## Генерация видео из изображения (image→video) — работает, E2E подтверждён

Проверено E2E (2026-11-13): картинка + промпт движения → mp4 (1280×720, ~10 с, h264+aac, ~6 МБ). Veo принимает картинку и промпт без отказа, движение соответствует промпту.

Команда: `gemini_ask.ps1 -Question '<промпт движения>' -FilePath <png> -VideoOut <mp4>` — пара `-FilePath` + `-VideoOut` автоматически включает режим `Create video`, печатает `VIDEOMODE_ON`, прикреплённую картинку (`ATTACHED`), затем скачивает по `Download video` и пишет mp4 ровно в `-VideoOut` (`SAVED:`).

Порядок, который реально работает (тот же, что у пользователя вручную):

1. Новый чат → включить `Create video` РЕАЛЬНЫМ mouse_event-кликом по пункту меню, с принудительным циклом off→on (если плейсхолдер уже `Describe your video` — сначала выключить, потом включить). Проверка включения — ValuePattern-плейсхолдер пустого редактора: `Describe your video` (ВКЛ) vs `Ask Gemini` (выкл). `TogglePattern.Toggle()` не годится: UI переключается, но запрос уходит текстовой модели → отказ «Я всего лишь языковая модель…».
2. Картинка через буфер: CF_HDROP (`Clipboard.SetFileDropList`, нужен STA) + клик в редактор + Ctrl+V → чип `close attachment` (`ATTACHMENTS>=1`). Ctrl+V — РАБОТАЕТ, если режим включён именно кликом; прежние отказы были из-за Toggle-включения (или севшего лимита), а не из-за вставки.
3. Промпт через `SetValue` + проверка первых 20 символов + Invoke кнопки `Send message`.
4. Ответ Veo: генерация 1–4 мин; в чате появляются кнопки `Download video`/`Share video`/`Mute video` (у video-карточки нет Image `AI generated`). Отказ детектируется по тексту `языковая модель`/`не могу помочь`.
5. Скачивание: Invoke `Download video` → через несколько секунд–минут открывается нативный Save As `#32770` с заголовком `blob:null/<guid>`. ВАЖНО: этот диалог НЕВИДИМ в UIA-дереве `root.FindAll(Children)` и `FindWindowExW` его не находит — искать только raw `EnumWindows` по классу `#32770`/префиксу `blob:`. Поле имени — вложенный `Edit` с ctrl id 1001 (`GetDlgItem(dlg,1001)` возвращает 0!; нужен `EnumChildWindows` + `GetDlgCtrlID`). Дальше `WM_SETTEXT` полного пути → `GetDlgItem(dlg,1)` + `BM_CLICK` (Сохранить) — файл ложится ровно по пути.

Про дневной лимит Veo: он аккаунтный; при исчерпании отказ/пауза — переключение на другой аккаунт в приложении разблокирует. Перед долгим прогоном имей это в виду и честно говори пользователю, если лимит сел.

Видеовыход всегда ~10 с 1280×720 h264+aac независимо от запрошенной длительности (ограничение Veo в этом приложении).

Коды выхода и ошибки:

- `0` — успех, ответ между маркерами.
- `ERROR_NO_WINDOW` (2) — приложение не запустилось за 45 с: попроси пользователя открыть Gemini и проверить, что он залогинен, затем повтори вызов (скрипт сам запускает exe, если приложение закрыто).
- `ERROR_NO_EDITOR` (3) / `ERROR_NO_SEND_BUTTON` (4) — интерфейс приложения изменился (обновление версии): см. диагностику ниже.
- `ERROR_NO_ANSWER` / `TIMEOUT_NO_ANSWER` (5) или строка `TIMEOUT_PARTIAL` перед ответом — Gemini не завершил генерацию за `MaxWaitSec`: сообщите пользователю, можно повторить с бо́льшим `MaxWaitSec`.
- `IMAGE_CAPTURE_FAILED` — картинка сгенерирована, но снять область экрана не удалось (окно перекрыто/свёрнуто): попроси пользователя не трогать окно Gemini и повтори.
- `VIDEO_DOWNLOAD_FAILED` — видео сгенерировано (кнопка `Download video` есть), но диалог сохранения не появился/файл не записан за 300 с: повтори прогон; убедись, что висящих `blob:`-диалогов не осталось.

## Дальнейшая работа

После получения ответа: верни его пользователю (при необходимости переоформив markdown) и продолжай исходную задачу ZCode, учитывая ответ Gemini. Если пользователь просил именно "спросить", а не "продолжить", ограничься передачей ответа.

## Диагностика сбоев

Если скрипт возвращает 3/4 — элементы UIA переименованы обновлением приложения. Разведка: найди окно с именем `Gemini` через `System.Windows.Automation`, поле ввода — `Edit` с именем, содержащим `prompt` (у него должен работать `ValuePattern`), кнопка отправки — `Button` с именем `Send message`. Обнови регулярки в `scripts/gemini_ask.ps1` (`Find-Editor`, `'^Send message$'`, `'Stop'`, маркеры конца в `Extract-Answer`) и перепроверь на коротком вопросе.

## Особенности, которые нельзя сломать

- Перед вводом скрипт включает флаг screen reader (`SPI_SETSCREENREADER`), иначе Chromium в Electron не строит дерево доступности и `Edit`/`ValuePattern` недоступны; в конце скрипт возвращает флаг в исходное состояние.
- `ValuePattern.SetValue` — единственный надёжный способ ввести текст (SendKeys/Ctrl+V и клики по координатам в Chromium не срабатывают).
- Сразу после перезагрузки приложения (обрыв сети) дерево UIA может быть ещё не построено: скрипт ждёт появления `Edit` до 20 с, прежде чем вернуть `ERROR_NO_EDITOR` — это не обязательно смена интерфейса.
- Каждый запуск открывает новый чат (кнопка `New chat`), иначе границы ответа между вопросами в одном чате не отделить.
- Ожидание ответа = нет кнопки `Stop` + текст всех `Text`-узлов стабилен 3 подряд проверки по 2 с. Не сокращай стабилизацию до 1–2 проверок: между частями генерации бывают паузы > 2 с.
- Ответ-картинка не содержит текста после «Gemini said», поэтому завершение засчитывается и по новому `Image`-элементу с именем, содержащим `AI generated` (ширина > 100 px), появившемуся после отправки (их число сравнивается с baseline до генерации — старые картинки из чата не считаются).
- Сохранение картинки (в `gemini_ask.ps1`): кнопка берётся по имени, содержащему `Download`, чей центр лежит в границах карточки нужного `Image` (допуск +80 px сверху и +120 снизу: пока blob грузится, карточка «схлопнута» до h≈16 px, а тулбар с кнопками уже висит под ней; при медленной сети кнопка неактивна — `Invoke` бросает `ElementNotEnabledException`, скрипт повторяет до 60 с; в чате несколько картинок — кнопка последней). После клика главный механизм — `Find-BlobDialog` (`EnumWindows`, класс `#32770`, заголовок начинается с `blob:`; диалог НЕвидим UIA-обходу от корня) → `Handle-SaveDialog`: поле имени = дочерний элемент с `GetDlgCtrlID()==1001` (вложен в DUI, `GetDlgItem(1001)` не находит), «Сохранить» = `GetDlgItem(dlg,1)`, «Отмена» = `GetDlgItem(dlg,2)`; ввод — `WM_SETTEXT` полным путём (директория проекта задаётся именно так, через путь в имени файла), нажатие — `BM_CLICK`. Диалог открывается НЕ сразу, а через ~2–3 мин после клика (ждём до 300 с) — короткие окна наблюдения 60–90 с его пропускают. После любого исхода вызывается `Cancel-LeftoverDialogs` — незакрытый диалог недопустим. Ставка гонки в конце: текст ответа мог стабилизироваться раньше отрисовки `Image`-карточки, поэтому после цикла ожидания ответа даём картинке ещё до 30 с появиться, иначе блок сохранения пропускается. Fallback при сбое — `Graphics.CopyFromScreen` по `BoundingRectangle`.
- Если обновление приложения переименует кнопку — в UIA-разведке искать `Button` с центром в углу `Image`-карточки (см. `Download full size image` в дереве выше).
- Видео-ответ не конфликтует с картинным: в видео-карточке нет `Image`/`ControlType.Video`, поэтому `Find-AiImages` на неё не срабатывает, а `Find-VideoButtons` (строгое `-eq 'Download video'`) — только на неё. Завершение ответа засчитывается и по новому числу `Download video` (baseline до отправки). `Handle-SaveDialog` принимает расширение (`'mp4'`) и пропускает `gemini_generated_video_xxx.mp4` через regex поля имени; для видео файл после диалога перемещается (`Move-Item -Force`) ровно на `-VideoOut`. Диалог тот же и обрабатывается тем же кодом — не плоди отдельный путь.
